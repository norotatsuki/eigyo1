# 営業リスト基盤 — 使い方

日本の全法人を手元に持ち、条件で切り出して営業に使うための土台。
**社内利用のみ**。リストを外部に提供する運用は想定していない (理由は
[構想書](./sales-platform-concept.md) §2.2)。

## 現在できること

| できること | 状態 |
|---|---|
| 全法人 581 万件の取り込み (国税庁) | 動作 |
| 閉鎖・除外の除去 (営業対象 500 万件を判定) | 動作 |
| 地域・法人種別・法人格・設立時期での絞り込み | 動作 |
| 商号の部分一致検索 (全角半角のゆれを吸収) | 動作 |
| CSV 書き出し | 動作 |
| **業種での絞り込み** | 器はあるが**データ未取得** (下記) |
| 資本金・従業員数での絞り込み | 器はあるがデータ未取得 |
| サイト URL・問い合わせフォームの特定 | 未実装 |
| メール送信・フォーム送信 | 未実装 |

## 必要なもの

- Node.js 22 以上
- `unzip` コマンド (macOS / Linux には標準で入っている)
- 空き容量 約 5GB (データベース 3.2GB + 生 zip 250MB)

## 準備

```bash
npm install
```

## 取り込み

```bash
# 全国 581 万件。約 5 分、zip 250MB のダウンロードを伴う
npm run cli -- ingest

# 小さく試したいとき
npm run cli -- ingest --region 鳥取県
```

国税庁のデータは毎月更新される。同じコマンドを流し直せば上書きされる
(法人番号を鍵にした更新なので、重複は増えない)。

## 絞り込む

```bash
# 東京都の株式会社
npm run cli -- search --pref 13 --kind 301

# 会社だけ (株式会社・有限会社・合名・合資・合同)
npm run cli -- search --companies --pref 13

# 商号に「システム開発」を含む先
npm run cli -- search --keyword システム開発

# 半角で打っても全角の商号に当たる
npm run cli -- search --keyword AIシステム

# 直近に設立された合同会社を新しい順に
npm run cli -- search --kind 305 --assigned-from 2025-01-01 --order assigned_desc
```

## 書き出す

```bash
npm run cli -- export --pref 13 --companies --out tokyo.csv
```

表計算ソフトでそのまま開ける形 (BOM つき UTF-8) で書き出す。

## 業種で絞り込むには

**業種は国税庁のデータに含まれていない。** 別の出典が要る。

第一候補は gBizINFO (経済産業省)。法人番号を鍵に、業種・資本金・従業員数・
法人サイト URL が取れる。利用には無料の利用者登録とアクセストークンが必要。

- 申請先: https://info.gbiz.go.jp/
- 一括ダウンロードとAPIの両方が提供されている
- **トークンを取得したら教えてください。取り込みを実装します**

トークンが手に入るまでの間も、地域・法人種別・設立時期・商号の語での
絞り込みは使える。商号の語 (「建設」「システム」「運輸」など) は
業種の代わりとしてかなり効く。

## 設計上の約束

### 営業対象の判定

法人番号は登記された全法人に振られるため、清算結了や合併で消えた法人が
80 万件以上含まれる。以下の 3 条件を満たすものだけを営業対象とする。

- 検索対象除外 = 0 (国税庁が公表対象から外していない)
- 登記記録の閉鎖等年月日が空 (清算結了・合併消滅などをしていない)
- 最新履歴等 = 1 (過去の履歴行ではない)

`--include-inactive` を付けると、この判定を外して全件を見られる。

### 営業お断りの尊重

`company_profiles.solicitation_refused` が 1 の先は、検索・書き出しから
既定で外れる。この列は今後のサイト収集で埋める。外すには
`--include-refused` を明示的に付ける必要がある。

### 商号の正規化を 2 つに分けている理由

- `name` … 国税庁の正式表記。表示・郵送に使う。**加工しない**
- `name_normalized` … 全角半角のゆれだけを吸収した形。検索の索引はこちら
- `name_core` … 法人格・記号・空白を落として詰めた形。名寄せの照合キー

所在地も同じ考えで、正式表記のまま保持している。

## データの置き場所

```
data/
├── eigyo.db          # SQLite。3.2GB
└── raw/              # 国税庁から取得した zip
```

`data/` は git の管理外。公的データなので、消しても取り込み直せる。

データベースの位置は環境変数 `EIGYO_DB` か `--db` で変えられる。

### なぜ SQLite か

社内利用で、まず動かすことを優先したため。サーバの用意が要らず、
581 万件でも検索は 1 秒以下で返る。複数人が同時に書き込む段階になったら
PostgreSQL に移す。読み取りだけなら SQLite のままで複数人が使える。
