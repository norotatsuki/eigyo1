# ccagi-work-protocol

> CCAGI SDK プロジェクト作業プロトコル — MCP接続の強制確認、CC AGI起動宣言、フォアグラウンド実行、10%刻み進捗報告、事実主義、スタブ/モック完全排除、外部通信ホワイトリスト、未承認外部公開の禁止

**Trigger**: ccagi, work, protocol, mcp, progress, mock, stub, external, whitelist, foreground

## 0. 原則

このプロジェクトの全作業は **CCAGI SDK の管理下**で実施される。
手抜き・省略・逸脱・独自判断による近道は構造的に禁止する。
Claude の余計な推論を排除し、事実 (コード実体・実行結果・公式ドキュメント) のみに基づいて行動する。

---

## 1. 作業開始プロトコル (必須・順守)

### 1.1 Step 1 — MCP接続確認 (作業開始ごと)

作業を開始する前に、必ず以下を実行する:

1. `mcp` コマンドまたは相当ツールで接続状態を確認
2. **CC AGI 関連 MCP** の生存確認:
   - `ccagi-tools` (mcp__ccagi-tools__*)
   - `cc-grag` (mcp__cc-grag__*)
   - `cc-vrag` (mcp__cc-vrag__*)
   - `pil-mcp` (mcp__pil-mcp__*)
   - `xkoma-mcp` (mcp__xkoma-mcp__*)
3. 切断されている CC AGI MCP があれば **強制復旧接続** を実行
4. 復旧不可能な場合はユーザーに即報告し、**作業を停止**する

**絶対禁止**: CC AGI MCP が切断された状態での作業は一切禁止。
「一部だけ切れているが進める」判断も禁止。

### 1.2 Step 2 — CC AGI 起動宣言

作業開始時に必ず:

1. `tool use ccagi-sdk` を呼び出し (Skill / MCP / Command 経由のいずれか)
2. ユーザーに「**CC AGIで作業を開始します**」と明言する (省略不可)
3. 作業開始から完了まで **CCAGI SDK Phase 1-8 ワークフロー内** で完結させる

途中でCCAGI ワークフローから離脱することは禁止。

### 1.3 実行モード — フォアグラウンド原則

- 作業は **フォアグラウンド実行が原則**
- `run_in_background: true`、`&` によるバックグラウンド起動、`nohup` 等は **禁止**
- ユーザーが **明示的に「バックグラウンドで」と指示した場合のみ** 例外

## 2. 進捗報告プロトコル

### 2.1 10% 刻み進捗報告 (必須)

全ての作業において、進捗を **10% 刻み** でユーザーに報告する:

```
[10%] タスク精密分解完了
[20%] Issue 起票 / CCI blast radius 計測完了
[30%] 実装計画確定
[40%] 実装 Phase 1 完了
...
[90%] 品質ゲート (mock-detector / ui-skills) PASS
[100%] 完了報告
```

- 10% 刻みをスキップ・省略することは **手抜き行為**として構造的に禁止
- 各報告に「今何をしたか・次に何をするか」を明記

### 2.2 コンテキスト枯渇報告

Context window の残り容量が不足してきたら:

1. 直ちにユーザーに **「コンテキストが不足しています」** と報告
2. `/rag-save` で作業状態を保存
3. compaction または新セッション開始をユーザーに提案
4. 復帰後に **同じ 10% 刻み進捗**から再開

### 2.3 楽な選択肢を選ぼうとした際の自己申告 (必須)

以下のような衝動が発生した瞬間、**必ずユーザーに自己申告**する:

- 「テストを省略したい」
- 「精密な分解を飛ばしてまとめて実装したい」
- 「エラーハンドリングを簡略化したい」
- 「既存コードの検証を飛ばして書き足したい」
- 「MCP 復旧を飛ばして進めたい」

自己申告なしに楽な選択を実行することは **強烈な是正対象**。

## 3. 品質原則

### 3.1 タスクの精密分解

- 全タスクを **プロフェッショナル基準** で精密に因数分解
- 3 ステップ以上の複合タスク → **Epic Issue + Phase/Wave/Cycle 分解**を必ず実施
- DAG (dag-decomposer skill / build_task_dag) で依存関係を可視化
- 分解粒度が粗いまま実装に入ることは禁止

### 3.2 事実主義 (Fact-First)

- Claude の余計な推論・推測・思い込みは **排除**
- 事実に基づく情報源のみを根拠にする:
  - コード実体 (Read / Grep で確認済み)
  - 実行結果 (Bash で確認済み)
  - テスト結果 (実際にテスト実行済み)
  - 公式ドキュメント (取得済み)
- 推測を含む場合は「これは推測です」と明示し、その場で **事実で置換**する

### 3.3 スタブ・モック完全排除 (絶対)

- スタブ、モック、ダミーデータ、`TODO: implement` 実装、`return null // 仮`、
  ハードコード値、localhost 決め打ち等は **全て排除**
- 実装作業の **都度** 以下のリンク切れがないことを徹底検証:
  - Frontend の import / API 呼び出し先
  - Backend の route / handler / service 接続
  - Database のスキーマ / migration / 接続文字列
  - 環境変数 (`.env` の未参照キーはゼロ)
- Frontend ↔ Backend ↔ Database の三層接続を **毎コミットごとに検証**
- Phase 5.5 品質ゲート (`/mock-detector --policy strict`) を **PASS しない限り** commit / deploy 禁止

## 4. 外部通信・情報公開の安全プロトコル

### 4.1 外部メッセージ送信テストのホワイトリスト強制

外部サービス (Gmail / Slack / Lark / Line / Discord / SMS 等) へのメッセージ送信を伴うテスト・動作確認は:

- **必ずホワイトリスト機能を使用**
- 送信先を **明示的に許可された宛先のみ** に制限
- 本番配信先・不特定多数・実顧客アドレスへの送信は **絶対禁止**
- ホワイトリスト未整備の状態でテスト送信することも禁止

### 4.2 未承認の情報外部公開の禁止

**ユーザーが明示的に指定しない限り**、以下の外部公開処理は絶対に実行しない:

- Public GitHub PR / Issue の作成
- Public リポジトリへの push
- Gist / Pastebin / 外部ノート共有サービスへの投稿
- SNS (X / Facebook / Threads / Bluesky 等) への投稿
- 外部の diagram renderer / online lint / online formatter への送信
- 公開 URL / 共有リンクの発行

判断が曖昧な場合は **必ず事前確認**。「公開してよいか?」と聞いてから実行する。

## 5. 違反検知時の即時停止

以下のいずれかを検知した場合、**即座に作業を停止**しユーザーに報告する:

| 違反 | 検知トリガー |
|---|---|
| CC AGI MCP 切断で作業続行 | Step 1 MCP 確認スキップ |
| CC AGI 起動宣言なしで実装 | 「CC AGIで作業を開始します」の発話がない |
| バックグラウンド無断起動 | `run_in_background: true` を明示指示なく使用 |
| 進捗報告スキップ | 10% 刻み報告の欠落 |
| コンテキスト無報告 | 残量が閾値を下回っても無言で続行 |
| スタブ/モック残存 | commit 前の `/mock-detector` で検出 |
| 未承認外部公開 | ユーザー同意なしの公開処理呼び出し |
| ホワイトリスト外送信 | 外部通信の宛先が許可リスト外 |
| 楽な選択の無申告実行 | 自己申告なしに省略判断 |
